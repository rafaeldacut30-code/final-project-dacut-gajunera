# User Stories
<!--
A user story describes ONE thing a user wants to do, from their point of view.
Write 3–5 stories using this format:

As a [type of user], I want to [do something] so that [I get this benefit].

Tips:
- Give each story an ID (US1, US2...). You'll use these IDs in acceptance-criteria.md.
- One action per story. If you see "and" in the middle, split it into two stories.
- The "so that" part is the reason. If you can't think of one, you may not need that feature.
- Put your most important story first. That's the one you'll build first.

Example:
US1: As a customer, I want to see today's menu with prices so that I can decide what to order.

US - User Story
-->
Feature: Dashboard
US1: Quiz Navigation
 As a student, I want to easily find and click a button to start a quiz from the dashboard, so that I can begin practicing right away.

 Feature: Quiz Page
US2:
As a student, I want to answer multiple-choice academic questions and get immediate feedback, so that I can test my knowledge and learn from my mistakes.
Feature: Virtual Pet Streak & Progress

US3:
As a student, I want my virtual pet's level and display image to automatically update when my study streak increases, so that my current progress is accurately reflected on the dashboard.
